Project Summary

The goal of this project was to train a physics-based 3D ragdoll agent to compete in a simplified sumo-style environment using reinforcement learning. In the final version of the project, the long-term objective was for two ragdoll agents to balance, move, and push each other out of an arena. However, because multi-agent sumo wrestling is a difficult continuous-control task, the project was developed through curriculum learning. Instead of immediately training an agent against another moving opponent, we first trained a single ragdoll agent to balance, walk toward a heavy block, and push that block out of the arena. This problem is difficult because the ragdoll must coordinate many joints in a continuous physics environment, where small changes in movement can cause the agent to lose balance or fail the task. A hand-coded controller would be difficult to design manually, so reinforcement learning is useful because it allows the agent to discover movement strategies through repeated interaction with the environment.

This simplified task served as a proof of concept for the larger sumo objective. Before an agent can compete against another agent, it must first learn basic locomotion, body control, and object interaction. The final prototype demonstrates meaningful progress toward this goal: after multiple reward-function iterations and more than 45 million training steps, the agent learned a relatively stable walking behavior and could move toward the block and knock it out of the arena. A major theme of this project was reward shaping. Although reinforcement learning allows agents to discover behavior through trial and error, it also creates opportunities for reward hacking. Across training versions, the agent repeatedly found unintended ways to maximize reward, including sliding across the floor, crawling in a plank-like pose, and bridging off its head. These behaviors were not failures of the algorithm alone; instead, they revealed weaknesses in the reward function and environment design. As a result, the project became an iterative process of observing agent behavior, identifying loopholes, modifying the reward structure, and retraining the agent.

Approaches

Baseline Approaches

Because the final goal of training two ragdoll agents to compete in sumo wrestling was too complex to begin with directly, we treated the earlier reward-function designs as baseline approaches. Each baseline used the same general reinforcement learning setup, but with a simpler or less constrained reward function. Comparing these versions helped show why reward shaping was necessary for this task.

The first baseline, version 0.1, rewarded the agent for pushing the block out of the arena using a dense progress reward and an existential penalty. This approach was simple and gave the agent a clear objective, but it did not properly constrain how the agent should move. As a result, the agent learned to slide across the floor instead of walking. This showed that rewarding task completion alone was not enough because the agent could maximize reward through physically unrealistic behavior.

The second baseline, version 0.2, added penalties when the chest or hips touched the floor, along with a small reward for keeping the head elevated. This improved the previous version by discouraging full-body sliding. However, the agent still found an unintended solution: it learned to crawl or move in a plank-like position while using its limbs to avoid the floor-contact penalty. This version demonstrated that partial body-contact penalties were not strict enough to produce stable walking.

The third notable baseline, version 0.5, made the task harder by increasing the block weight, moving the block farther away, and rewarding the agent for reducing its distance to the block. A hip-height threshold was also added so that the episode would reset if the agent fell too low. This version produced the first signs of walking, but the agent still exploited the reward function by walking briefly and then sliding sideways into the block. Although this was closer to the intended behavior, it still did not reliably produce controlled locomotion.

These baseline approaches were useful because they revealed the main difficulty of the project: the agent did not simply learn the behavior we wanted. Instead, it learned whatever behavior maximized the reward. Therefore, the final approach needed stronger constraints on balance, body contact, and movement quality.

Proposed Approach: PPO with Curriculum Learning and Reward Shaping

The final approach uses Proximal Policy Optimization (PPO) through Unity ML-Agents to train a physics-based ragdoll agent in a simplified block-pushing environment. PPO was chosen because the agent operates in a continuous-control environment where each action controls joint movement rather than selecting from a small set of discrete actions. Since the ragdoll has many body parts, rotations, velocities, and joint states, the policy must learn to coordinate a high-dimensional action space.

The project also uses curriculum learning. Instead of immediately training two agents against each other, the task was simplified into a single-agent environment where the ragdoll learns to walk toward and push a heavy block out of the arena. This curriculum step is important because a sumo agent must first learn basic locomotion, balance, and object interaction before it can compete against another moving opponent.

At each time step, the agent receives observations from its body and the environment. These observations include body-part positions, rotations, velocities, joint information, height from the ground, target position, and relative distance to the block. The action space consists of continuous joint-control values that determine how the ragdoll moves. The reward function encourages the agent to stay upright, move toward the block, and push the block out of the arena, while penalizing falling, unstable body contact, and unintended movement strategies.

The purpose of this reward function was not only to complete the task, but to complete it in a way that resembled the intended behavior. This distinction was important because the agent often found ways to receive reward without truly walking. By making invalid body contact more costly, the final version forced the agent toward more stable locomotion.

Training Procedure

The training process followed an iterative cycle of training, observing, diagnosing failure cases, modifying the reward function, and retraining. This process was necessary because the reward graphs alone could not show whether the agent was actually walking. Each version had to be visually inspected inside Unity to determine whether the behavior was valid.

The overall training loop used for the ragdoll agent alternates between collecting trajectories in the Unity physics environment, computing rewards based on balance and task progress, and updating the PPO policy using the collected experience. At each step, the agent observes its body state, selects a continuous joint-control action from the current policy, applies that action in the Unity physics simulation, and receives rewards or penalties for progress, upright posture, falling, and invalid body contact. Successful block-pushing ends the episode with a success reward, while falling ends it with a failure penalty. Collected trajectories are then used to estimate advantages and update the PPO policy with a clipped objective.

The advantage of this approach is that it allows the agent to learn complex movement without requiring a manually programmed walking controller. It also allows the reward function to be refined based on observed behavior. However, the disadvantage is that training is time-consuming and highly sensitive to reward design. Small changes in penalties or reset conditions can produce very different behaviors.

Advantages and Disadvantages of the Final Approach

The main advantage of the final approach is that it successfully produced more stable walking behavior than the earlier baseline versions. By combining PPO, curriculum learning, and stricter reward shaping, the agent learned to move toward the block and knock it out of the arena after more than 45 million training steps. This showed that the simplified curriculum task was useful for developing the foundational skills needed for a future sumo agent.

Another advantage is that the approach is flexible. The same framework can be extended from block pushing to multi-agent sumo by replacing the block with another ragdoll agent and modifying the reward function to include opponent position, ring boundaries, pushing success, and falling conditions.

The main disadvantage is that the agent is still vulnerable to reward hacking. Even when the reward function appears reasonable, the agent can discover unintended strategies that satisfy the reward mathematically but do not match the intended behavior. Another limitation is that the final behavior is still clumsy and not fully natural. The agent can walk and push the block, but it does not always use its hands or arms in a controlled way. This suggests that future versions will need more refined rewards for hand-based pushing, balance recovery, and efficient movement.

Overall, the final approach improved significantly over the baseline reward functions. The project demonstrates that PPO can train a ragdoll agent in a difficult continuous-control environment, but it also shows that careful reward design and qualitative evaluation are essential for producing meaningful behavior.

Extension to Self-Play and Policy Degradation

Extending the single-agent block-pushing policy to a two-agent self-play environment introduced challenges that were absent from the single-agent task. The core difficulty is that self-play is non-stationary: each agent is trained against an opponent that is itself changing, so the environment an agent faces is never fixed. A policy that performs well against one version of its opponent is not guaranteed to perform well against the next, and improvements made against a weak opponent can be undone once that opponent improves. Unlike the block-pushing task, where the target is a static block, there is no stable objective to converge toward.

This non-stationarity manifested as policy degradation early in self-play training. When the single-agent policy was first placed in the competitive environment, it had to contend with two changes at once: the introduction of an active, moving opponent in place of a passive block, and the expansion of the observation space to include the opponent's state. Matches briefly became shorter before recovering, reflecting that the transferred policy is initially destabilized by the new setting and falls more easily, before adapting to the presence of an opponent and climbing back toward the equilibrium plateau. In other words, the carefully learned balancing behavior partially degraded before it recovered in the new task.

Because the reward signal in this setting is zero-sum and noisy, it provided little guidance for diagnosing these failures; degradation was identified instead through the episode-length curve and by replaying matches in Unity. The recovery of episode length to a stable plateau indicates that the agents eventually reached a competitive equilibrium in which both could maintain balance against an active opponent, but the modest size of the final gains shows that self-play remained difficult to stabilize and is the clearest direction for future improvement.

Evaluations

We evaluated training using the two scalar metrics that TensorBoard logs throughout each run: mean cumulative reward and mean episode length. A central difficulty in interpreting these curves is that neither metric is meaningful on its own. Because an episode terminates either when the agent falls or when it succeeds by pushing the block out of the arena, a short episode can indicate either an early fall or a quick success. We therefore read episode length and cumulative reward jointly, and cross-checked candidate policies by replaying them inside Unity rather than trusting the scalar curves alone.

Block-Pushing Task

The block-pushing runs followed a three-phase arc. Early in training, episodes are very short and reward is very low: the agent is falling over, ending episodes almost immediately. In the middle phase, episode length rises steeply, peaking near 250 steps around 25 million training steps. Read in isolation this looks like the agent stalling, but read alongside reward we see that the agent has learned to keep its balance, so it survives far longer without triggering the fall condition. In the final phase, episode length falls back toward roughly 60 while reward continues to climb, rising from about 1-2 to roughly 6 between 30 million and 40 million steps. This decrease is the desired outcome, not a regression. The agent is no longer falling over; instead it has become faster at completing its objective, so successful episodes terminate early through the success condition and return a large reward. Because episode length and reward move in opposite directions, we read this as task acquisition rather than some kind of reward-hacking: the agent first learns not to fall, and then learns to finish its task quickly.

A later run resumed from the converged policy of the initial run and applied further reward tuning. The flat curves reflect incremental refinement of a converged policy rather than learning from scratch.

A critical part of the evaluation was qualitative. While the functions were valuable, they only told half the story; watching the agent move was more informative with regards to the quality of the movement. For example, in earlier iterations the agent achieved high reward but sacrificed the integrity of its walk. We closely monitored the agents progression in Unity to make sure their walk, sense of balance, and overall mechanics looked good.

Self-Play

After establishing single-agent movement, we extended the environment to self-play, in which two ragdoll agents are trained against each other. Here the reward is essentially zero-sum: agents are rewarded for winning and penalized for losing, so one agent's gain is the other's loss. The reward curve is dominated by high-frequency variance around a roughly flat mean of about 1.5, which is roughly what we would expect a self-play run looks like rather than a sign of failure to learn: because each agent's reward is defined against a continuously improving opponent, the mean reward stays flat even as both policies improve. Cumulative reward is therefore a poor progress metric in this setting.

The episode-length curve is the more informative signal. An episode ends when an agent falls down, so episode length is a direct measure of how long the agents can stay on their feet against an active opponent. The curve dips slightly early in training, around 30 steps, and then climbs steadily to a plateau near 33 steps by roughly 20 million steps. Longer matches mean that neither agent can put the other on the floor as quickly as before---both agents have become harder to topple, which is consistent with the two policies converging toward a competitive equilibrium where each has to struggle more for a win. The absolute gains here are modest, so we regard self-play as only mildly successful: the agents became more difficult to knock down, but did not develop markedly more sophisticated strategies. We also note that these self-play episode lengths occupy a much narrower and lower band (30-33) than the block-pushing runs (50-250), reflecting the different termination dynamics of competitive matches, so the raw lengths are not directly comparable across the two tasks.

References and Resources Used

The main resources used for this project were Unity, Unity ML-Agents, C#, Proximal Policy Optimization, TensorBoard, and our project repository. Unity was used to create the 3D physics environment and simulate the ragdoll agent. Unity ML-Agents was used as the reinforcement learning framework for training the agent with PPO. C# was used to implement the agent behavior, observations, actions, rewards, penalties, and reset conditions. TensorBoard was used to monitor training progress through metrics such as mean cumulative reward and mean episode length.
